What gets mapped automatically

A servers entry becomes your workspace Base URL (optional, on by default). Each securitySchemes entry becomes a token variable, wired into the right header, cookie, or query parameter for every operation that requires it.

openapi: 3.0.3
servers:
  - url: https://api.example.com/v1
paths:
  /users/{id}:
    get:
      security:
        - bearerAuth: []
      parameters:
        - name: id
          in: path
          required: true
          schema: { type: string }
components:
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer

Frequently asked questions

What OpenAPI versions does Devman API support?

Devman API imports OpenAPI 3.x documents in JSON or YAML. For Swagger 2.0 documents, see the dedicated Swagger testing page.

Does Devman API set the Base URL from the OpenAPI servers field?

Yes, optionally. When importing, you can choose to use the first server URL from the document as your workspace Base URL.

How does Devman API map OpenAPI security schemes to tokens?

Bearer, basic, and API key (header, cookie, or query) security schemes are mapped to token variables automatically, so each secured operation sends the right auth without manual header editing.

Can I import an OpenAPI YAML file, or only JSON?

Both. Devman API parses OpenAPI documents in JSON or YAML, from a direct file URL or discovered from a Swagger UI page.

Does Devman API support OpenAPI request examples?

Yes. Path, query, header, and cookie parameter examples, and JSON/text/URL-encoded/multipart/binary request body examples, are used to prefill each imported request.
