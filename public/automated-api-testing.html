Automated API testing in the browser

Define a suite once — staged order, captured variables, jq assertions, and expected status codes — then run the whole flow automatically. Devman API retries transient failures and reports pass, bug, and fail counts without any manual re-testing.

Start testing free

A suite is a small JSON file

Each step can capture values from its response, assert on the result with jq, and expand over a list with foreach. Later steps reuse captured values as ${VARIABLE} placeholders.

{
  "steps": [
    {
      "name": "create user",
      "stage": 10,
      "method": "POST",
      "path": "/users",
      "expect_status": 201,
      "assert": ".data.id != null",
      "capture": { "USER_ID": ".data.id" }
    },
    {
      "name": "read user",
      "stage": 20,
      "method": "GET",
      "path": "/users/${USER_ID}",
      "expect_status": 200,
      "continue_on_fail": true
    }
  ]
}

What runs automatically

Requests run in stage order, capturing tokens and IDs from one response for reuse in the next. Transient network and server errors are retried with bounded backoff. Expected status codes and jq assertions are checked on every run, and a Markdown report can be exported when the suite finishes.

Frequently asked questions

What does "automated API testing" mean in Devman API?

It means defining a suite of requests once, with staged execution order, response captures, and jq assertions, then running the whole suite with one click instead of re-sending requests by hand.

Does Devman API retry failed requests automatically?

Yes. Transient network and server failures are retried automatically with bounded retries, and the retry count is shown on the result.

Can I run the same request against a list of values automatically?

Yes, using foreach in a suite JSON file. One step definition expands into a request per value in the supplied list.

Does Devman API validate responses automatically?

Yes. Set an expect_status and an optional assert (a jq expression or array of expressions) on each step, and Devman API checks them automatically when the suite runs.

Can automated API tests run outside the browser, e.g. in CI?

Not yet. Devman API runs in the browser and has no headless CLI runner today. Workspaces export as JSON suites you can version and re-import.
