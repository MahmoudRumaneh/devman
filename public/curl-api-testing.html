Test APIs by pasting cURL commands

Already have a cURL command from your browser's dev tools, a teammate, or your API docs? Paste it straight into Devman API — method, URL, headers, cookies, and body are all imported into a request-ready row.

Start testing free

Paste it as-is

Devman API detects the shell syntax automatically, so you can paste a command copied from Bash, PowerShell, or Windows Command Prompt without reformatting it first.

curl 'https://api.example.com/users' \
  -X POST \
  -H 'authorization: Bearer ${API_TOKEN}' \
  -H 'content-type: application/json' \
  --data '{"name":"Ada"}'

What's imported, what isn't

The HTTP method, URL, headers, cookies, and request body (raw, URL-encoded, multipart, or binary) are all imported. File paths mentioned in -F or --data-binary flags are never read from disk automatically — reselect the file in the browser before running that request, for security.

Frequently asked questions

Which cURL syntaxes does Devman API support?

Bash (single-quoted, backslash line continuations), PowerShell (backtick continuations), and Windows Command Prompt (caret continuations) cURL commands are all parsed.

Does pasting a cURL command import headers and cookies?

Yes. Headers, cookies, the HTTP method, the URL, and the request body are all imported from the pasted command into a request-ready row.

Can I import a cURL command with a file upload (-F)?

Yes, multipart form fields including file-upload placeholders are recognized. You still select the actual file in the browser before running the request; see the next question.

Does Devman API read local file paths from a copied cURL command?

No. File paths referenced in a pasted cURL command are never read automatically, for security reasons. Select the upload file again in the browser before running that request.

Can I paste multiple cURL commands at once?

Yes. Paste several complete cURL commands into the same box and each one becomes its own request row.
